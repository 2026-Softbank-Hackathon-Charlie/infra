# 0002. 권한이 필요한 감사·변경 작업에 사전 승인 적용

- 날짜: 2026-11-02
- 상태: 채택
- 관련 ADR: [0001. Agent의 주요 의사결정을 ADR로 기록](0001-record-decisions-as-adrs.md)

## 배경과 제약

사용자는 토큰 발급·등록이나 인프라·클라우드 설정의 직접 수정처럼 권한이 필요한 audit 작업을 승인받은 뒤 수행하도록 요청했다.
점검 요청만으로 자격 증명 발급이나 실제 환경 변경까지 허용되었다고 해석하면 사용자가 검토하지 않은 작업이 실행될 수 있다.

## 검토한 대안

- 포괄적인 작업 요청을 실행 승인으로 해석: 작업은 빠르지만 실제 변경 대상과 필요한 권한에 대한 사용자 검토가 누락될 수 있다.
- 모든 로컬 분석·문서 수정까지 매번 승인: 통제는 가능하지만 권한이 필요하지 않은 준비 작업까지 지연된다.
- 구체적인 권한 작업에 사전 승인 적용: 로컬 준비와 검증을 진행하면서 실제 접근·변경 범위를 사용자가 검토할 수 있어 선택한다.

## 결정과 이유

[AGENTS.md](../../AGENTS.md)에 권한이 필요한 작업의 사전 승인 규칙을 추가한다.
토큰·자격 증명 관리, 권한이 필요한 비공개 조회·감사 로그 접근, IAM 및 인프라·클라우드·클러스터 변경은 대상·목적·작업·권한·영향을 설명하고 명시적 승인을 받은 뒤 실행한다.
조회 승인은 변경 승인으로 확대하지 않는다. 이미 명시적으로 승인받은 범위는 재사용하되 범위가 확대되면 추가 승인을 받는다.
승인 전에 가능한 로컬 분석과 수정안·검증 결과를 준비하며, 도구나 실행 경로를 바꿔 승인을 우회하지 않는다.
이 정책의 채택은 개별 권한 작업에 대한 실행 승인을 의미하지 않는다.

## 영향과 후속 작업

- 기대 효과: 사용자가 실제 접근·변경 범위를 확인하고 자격 증명 및 인프라 변경을 통제할 수 있다.
- 단점과 위험: 사용자 응답이 필요한 실행은 승인이 도착할 때까지 보류된다. 승인 범위가 모호하면 구체화가 필요하다.
- 필요한 후속 작업 및 검증: 실행 전에 기존 승인 범위를 확인하고, 승인받은 범위와 실제 수행 결과를 완료 보고에 남긴다. 문서 링크는 `make inventory-check`로 확인한다.
