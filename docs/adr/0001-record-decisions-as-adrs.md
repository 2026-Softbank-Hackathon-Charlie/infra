# 0001. Agent의 주요 의사결정을 ADR로 기록

- 날짜: 2026-11-02
- 상태: 채택
- 관련 ADR: 없음

## 배경과 제약

사용자는 Agent가 의사결정을 수행했을 때 `docs/adr/`에 그 내용을 기록하도록 요청했다.
이후 작업에서 결정의 배경과 선택 이유를 확인하고, 변경 시 이력을 추적할 수 있어야 한다.

## 검토한 대안

- 대화나 작업 완료 보고에만 기록: 작성은 간단하지만 저장소에서 결정 이력을 확인하기 어렵다.
- README에 모든 결정을 기록: 접근은 쉽지만 사용 안내와 결정 이력이 섞이고 개별 결정의 변경 관계를 추적하기 어렵다.
- `docs/adr/`에 결정별 문서를 작성: 별도 문서 관리가 필요하지만 배경·대안·이유와 변경 이력을 코드와 함께 관리할 수 있다. 사용자가 요청한 경로에도 부합한다.

## 결정과 이유

저장소 루트의 [AGENTS.md](../../AGENTS.md)에 Agent의 ADR 작성 의무를 명시한다.
이후 작업에 영향을 주는 결정은 [공통 템플릿](template.md)을 사용해 `docs/adr/NNNN-short-kebab-case-title.md`에 한국어로 기록한다.
단순 오탈자나 포맷 수정, 기존 결정을 그대로 따르는 반복 작업은 새 ADR 작성 대상에서 제외한다.
채택된 결정이 바뀌면 새 ADR로 대체하고 양쪽 문서를 연결한다.

## 영향과 후속 작업

- 기대 효과: 이후 Agent와 기여자가 기존 결정의 근거를 확인하고 일관된 방식으로 변경할 수 있다.
- 단점과 위험: 문서 작성 비용이 추가되며, 구현 변경과 ADR을 함께 관리하지 않으면 실제 상태와 기록이 달라질 수 있다.
- 필요한 후속 작업 및 검증: 주요 결정이 포함된 작업마다 ADR을 함께 작성하고 완료 보고에 경로를 명시한다. 새 문서는 README 파일 목록에 추가하고 `make inventory-check`로 확인한다.
